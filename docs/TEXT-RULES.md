# 文案硬性要求（所有面向用户的文本）

适用范围：界面文案、提示、按钮、通知、文档、README、激活页、错误信息、提交信息里给人看的部分。

## 一条总则

**写每一句之前问自己：删掉它，读者会失去什么？**

答不上来就删。答案只是「显得完整」「解释了原因」「体现我们做得多」——也删。

## 具体条款

1. **只写读者要据此行动的信息。** 他需要点哪里、填什么、等多久、失败时怎么办。
2. **不解释实现。** 文件名、协议版本、加密方式、存储位置、服务端结构，一律不写进用户界面。
3. **不做比较。** 不写「与 X 相同 / 不同 / 一致」。用户不关心别的作品、别的应用怎么算。
4. **不复述界面。** 标题已经写了「直连通道」，正文不要再解释这是直连通道。
5. **不写铺垫与总结。** 「值得注意的是」「简单来说」「总的来说」「需要强调的是」整句删。
6. **不自夸。** 「更安全」「更稳定」「大幅提升」这类没有依据的形容词不写。
7. **不写「为什么这么设计」。** 那是注释和文档的事，不是界面的。
8. **书面语。** 不用「其实」「就好」「一下」这类口语填充；一句话能说完不拆两句。
9. **一处信息只说一次。** 卡片标题、正文、按钮重复表达同一件事时，只留最必要的一处。
10. **错误信息必须给出下一步。** 「连接失败」不合格；「连接失败，请先停止小米运动健康」合格。

## 检查方式

改完文案后，逐句套一遍总则；README 与注释可以保留解释，但同样删掉铺垫、自夸与重复。
